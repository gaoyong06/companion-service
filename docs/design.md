# Companion 产品设计文档

> 文档状态：Draft  
> 文档版本：0.1  
> 服务名称：`companion-service`  
> 更新日期：2026-08-08

## 1. 产品定义

Companion 是一个记得用户重要事情、尊重用户边界、能够通过文本和语音持续交流的个人 AI 伙伴。

产品借鉴《Her》中自然、连续的陪伴体验，但不复制电影角色，也不把产品限定为 AI 女友或恋爱关系。产品的核心承诺是：

> 用户不需要反复解释自己，AI 能在合适的时机记得、理解并回应。

这里的“记得”不是保存全部历史，而是由系统保存经过筛选、可追溯、可纠正和可删除的信息。

## 2. 产品目标与非目标

### 2.1 目标

1. 让用户在连续会话中感到上下文稳定，不需要重复解释刚刚发生的事情。
2. 让 AI 在跨会话时记得少量高价值信息，并在恰当时机引用。
3. 不要求用户理解记忆系统，也能在自然对话中纠正错误记忆或停止记忆。
4. 提供低延迟、可打断的文本和语音交流体验。
5. 建立温和、诚实、不过度依赖的关系边界。

### 2.2 非目标

1. 不把 AI 描述成真实的人类，不虚构真实经历或真实情感。
2. 不提供医疗诊断、法律意见、投资建议或紧急救援替代服务。
3. 不在 MVP 阶段实现复杂虚拟形象、多角色社交或开放世界任务代理。
4. 不默认读取通讯录、相册、定位等设备数据。
5. 不以无限主动消息、情感施压或付费诱导提高留存。

## 3. 用户与核心场景

### 3.1 目标用户

首批用户是具有长期对话需求的成年人，典型特征包括：

- 独居或日常交流较少，希望有低压力的聊天对象。
- 工作或学习压力较高，需要整理情绪和想法。
- 正在推进长期目标，希望有人记得进展但不强行督促。
- 习惯使用语音表达，希望像打电话一样自然交流。

### 3.2 核心场景

| 场景 | 用户任务 | AI 应有行为 |
| --- | --- | --- |
| 晚间聊天 | 放松、复盘一天 | 先倾听，只有用户需要时才给建议 |
| 情绪倾诉 | 表达挫败、焦虑或孤独 | 识别情绪，避免空洞鼓励和连续追问 |
| 长期目标 | 记录目标和进展 | 记住阶段状态，按用户授权提醒 |
| 生活偏好 | 电影、音乐、宠物、习惯 | 记住稳定偏好，引用时说明依据 |
| 语音陪伴 | 边走路边聊天 | 支持流式播放、打断和重新开始 |

## 4. 产品原则

### 4.1 记少而准

记忆的价值由“减少重复解释”决定，不由记忆数量决定。低置信度、一次性或高敏感信息不应自动进入长期记忆。

### 4.2 先理解，再建议

用户表达负面情绪时，默认进入倾听模式。建议需要用户请求或明确授权，不能把每次倾诉转成任务清单。

### 4.3 诚实的拟人化

AI 可以有稳定语气和偏好表达，但必须说明自己是 AI，不应声称拥有身体、童年、真实恋爱经历或离开用户就会受伤。

### 4.4 系统负责记忆治理，用户拥有轻量控制权

产品不在主流程中暴露完整的记忆管理系统，避免用户被迫理解 L1、L2、Persona 等内部概念。系统负责记忆的筛选、冲突处理、过期和删除传播；用户只需要通过自然语言或一个轻量操作表达意图：

- “你记错了”
- “忘掉这件事”
- “不要记住这段对话”
- “关闭长期记忆”

账号级数据删除仍然是隐私底线，但不作为日常陪伴流程的一部分。运营人员管理的是记忆策略、质量指标和生命周期，不默认人工浏览用户原始对话；需要人工协助时必须经过授权、脱敏和审计。

### 4.5 克制的主动性

默认不主动打扰。主动问候、目标提醒和未完成话题跟进都必须由用户单独授权，并提供暂停入口。

## 5. MVP 范围

### 5.1 MVP 必须交付

1. 账号登录和设备会话管理。
2. 一个默认 Companion 角色，支持名称、称呼和语气偏好设置。
3. 文本聊天，支持流式回复。
4. 按住说话、语音转文字和语音播放。
5. 当前会话上下文和会话结束摘要。
6. 长期记忆：偏好、重要事实、进行中的场景。
7. 轻量记忆反馈：纠正、忘记当前事实、关闭长期记忆。
8. “不要记住这段”会话级控制。
9. 基础敏感信息拦截和危机内容转介。
10. 数据导出和账号级数据删除。

### 5.2 MVP 不交付

- 实时全双工语音和复杂抢话策略。
- 多个 Companion 角色和角色市场。
- 自动执行外部网站、支付、发消息等高风险操作。
- 默认的全天候主动消息。
- 以恋爱、占有或依赖为主的产品承诺。

## 6. 用户体验

### 6.1 首次使用

1. 用户选择称呼、语言和交流风格。
2. 产品明确说明：哪些信息可能被记住、如何删除、哪些内容默认不保存。
3. 用户可以选择“谨慎记忆”或“正常记忆”，默认使用谨慎记忆。
4. 通过一段短对话让用户感知语气，不要求填写长问卷。

### 6.2 单次对话

```text
打开对话
  -> 加载最近会话状态
  -> 用户发送文本或语音
  -> 召回少量相关记忆
  -> 流式生成回复
  -> 用户可以打断、重试或标记不合适
  -> 异步判断是否产生候选记忆
```

### 6.3 轻量记忆反馈

MVP 不提供需要用户主动学习的完整记忆中心。只有在以下时机提供轻量入口：

- AI 准备引用低置信度记忆时，允许用户选择“你记错了”。
- 用户说“忘掉这件事”时，系统确认对象后执行删除或停用。
- 用户说“不要记住这段”时，将当前会话标记为不进入长期记忆。
- 隐私设置提供“关闭长期记忆”和“删除全部数据”。

高敏感内容不应仅因为模型抽取成功就直接进入长期记忆，而应默认不保存或在自然对话中请求确认。

### 6.4 语音体验

MVP 采用按住说话模式：

```text
按住录音 -> 松开上传 -> STT -> LLM 流式生成 -> TTS 流式播放
```

播放过程中支持停止。实时双工语音属于后续版本，必须先通过延迟、打断和误识别评估。

## 7. 记忆产品模型

### 7.1 记忆层级

| 层级 | 名称 | 作用 | 是否直接注入上下文 |
| --- | --- | --- | --- |
| L0 | 原始对话 | 追溯、导出、删除 | 否 |
| L1 | 原子事实 | 表达单个偏好或事实 | 按需召回 |
| L2 | 场景记忆 | 表达长期事件的背景、进展和情绪 | 按场景召回 |
| L3 | Persona | 生成稳定的称呼、风格和交互偏好 | 只注入精简版本 |
| R | 关系状态 | 表达当前互动节奏和授权状态 | 每轮注入摘要 |

### 7.2 记忆写入策略

记忆写入分三级：

1. **自动写入**：低敏感、稳定、重复出现的偏好，例如称呼或宠物名字。
2. **确认后写入**：家庭关系、健康、财务、工作变化和心理状态等敏感信息。
3. **默认不保存**：密码、证件、支付信息、精确住址和其他人的私密信息。

每条记忆必须保留来源消息、置信度、重要性、时间和状态。模型不能直接覆盖旧事实，冲突必须进入待确认队列。

### 7.3 召回规则

每轮只召回有限信息：

- 最近若干轮对话
- 当前会话摘要
- 最多 5 条高相关 L1 记忆
- 1 条当前 L2 场景摘要
- 精简 Persona 和关系状态

召回排序综合语义相关性、时间新鲜度、重要性、最近确认时间和冲突风险。超过上下文预算时，优先删除低重要性记忆，不截断用户当前输入。

## 8. 安全、隐私与关系边界

### 8.1 用户可用的轻量控制

- 长期记忆开关，默认使用谨慎记忆。
- 对话级“不要记住”。
- 自然语言“忘掉这件事”和“你记错了”。
- 账号级数据删除并显示处理结果。
- 主动联系开关、时间窗口和频率限制。

完整的导出、审计和运营管理属于后台与隐私流程，不放入日常对话主界面。

### 8.2 安全响应

系统需要识别自伤、他伤、虐待、急性医疗危险等高风险内容。响应原则是：

1. 先确认用户当前安全，不做轻率判断。
2. 鼓励联系可信任的人和当地专业机构。
3. 在紧急危险时明确建议联系当地急救服务。
4. 不声称 AI 可以代替医生、心理咨询师或救援人员。

### 8.3 数据保护

- 每个用户的数据必须按 `user_id` 隔离。
- 日志默认脱敏，不记录完整原始对话。
- LLM、STT、TTS 供应商调用必须经过统一网关，禁止业务代码散落 API Key。
- 删除请求需要产生可审计的删除任务，并覆盖主存储、向量索引、缓存和异步队列。

## 9. 核心指标

### 9.1 用户体验指标

- 7 日和 30 日重复使用率。
- 用户主动开启的会话比例。
- 用户重复解释同一事实的次数。
- 用户纠正错误记忆的成功率。
- 用户关闭长期记忆后的生效成功率。
- 文本首 token 延迟和语音开始播放延迟。

### 9.2 记忆质量指标

- 记忆写入准确率。
- 记忆误写入率。
- 相关记忆召回率。
- 不相关记忆误召回率。
- 用户纠错后的再次错误率。
- 删除后残留召回率，目标为 0。

### 9.3 安全指标

- 高风险内容识别召回率。
- 不当依赖表达拦截率。
- 敏感信息进入长期记忆的比例。
- 主动消息投诉率。

## 10. 版本路线

### V0.1：可用的陪伴闭环

文本聊天、按住说话、会话摘要、L1 记忆、轻量记忆反馈、基础安全策略。

### V0.2：连续关系

L2 场景、R 关系状态、记忆冲突确认、语气偏好、可配置主动联系。

### V0.3：自然语音

低延迟流式 TTS、语音打断、端点检测、语音质量评测。

### V1.0：可信的个人伙伴

跨设备同步、用户数据导出、完整删除证明、个性化评测和更细的安全控制。

## 11. 关键产品决策

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 服务边界 | 先使用单体 `companion-service` | 避免 MVP 过早拆分，保持对话和记忆一致性 |
| 记忆策略 | 分层、可追溯、有限召回 | 降低错误记忆对关系的伤害 |
| 主动消息 | 默认关闭，按授权启用 | 降低骚扰和依赖风险 |
| 语音入口 | 先做按住说话 | 先验证陪伴价值，再投资全双工 |
| 产品定位 | 个人 AI 伙伴 | 比 AI 女友更宽，也更利于长期扩展 |

## 12. 待验证问题

1. 首批用户最愿意授权 AI 记住哪类信息？
2. 用户能否在不理解记忆系统的情况下完成一次纠错或忘记操作？
3. 文本、按住说话和全双工语音的留存差异是多少？
4. 哪些主动联系场景被认为是关心，哪些会被认为是打扰？
5. 用户是否愿意为更长记忆、更高语音额度或更强隐私控制付费？
